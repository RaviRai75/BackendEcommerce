# Versioned manual fulfillment for normal orders

Task 23 adds the six explicit ADMIN fulfillment actions with expected-version CAS, a transactionally coupled manual Shipment aggregate, atomic cancellation release, and strict audit writes. Customer and administrator projections are separate, and unknown commits are reconciled through a private history marker. The unresolved gaps affect mutation acknowledgement, cross-collection DTO consistency, and shipment identity indexes. **Watch for:** **confirmed (high)** a committed action can be reported as failed when its post-commit reload fails; **confirmed (medium)** detail responses can combine different order/shipment versions; **likely (medium)** shipment uniqueness is scoped to MANUAL rather than courier/AWB identity.

**Verdict**: NEEDS_CHANGES

## High-level view

`START_PROCESSING`, `MARK_PACKED`, `RECORD_SHIPMENT`, `MARK_OUT_FOR_DELIVERY`, `MARK_DELIVERED`, and `CANCEL` are closed, one-way contracts. Each order mutation compares and increments `__v`; shipment transitions, delivery timestamps, resource release, and strict audit participate in the same transaction where applicable.

Unknown outcomes retry only `commitTransaction`, then majority-read a request/action/version/actor marker from the primary. A separate detail reload is still mandatory after a known or reconciled commit, so a read failure can make the API report failure after the mutation is durable.

Customer/admin output is allowlisted and admin routes are database-authorized and `private, no-store`. Order and Shipment are loaded in separate operations, allowing one response to combine states from before and after a concurrent transition.

Shipment indexes enforce one FORWARD shipment per order and unique manual tracking/private IDs. They leave courier/AWB unguarded and put every courier in one MANUAL identifier namespace.

<details><summary>Details</summary>

## A known commit can still surface as a failed action

**Confirmed — high.** `orderFulfillmentService.performAction` completes `runTransaction`, including strict audit and unknown-result reconciliation, then calls `loadAdminOrder` outside that transaction. If this read fails after `commitTransaction` succeeded—or after the marker proved it succeeded—the request returns an error although the action is durable. A client cannot safely replay the body because a new internal marker is generated and the old `expectedVersion` now conflicts.

The mutation response must not depend on a fresh, fallible multi-query reload. Return a committed version/status receipt, or explicitly retry and degrade the enrichment while still acknowledging the known commit. Affected symbols: `orderFulfillmentService.performAction`, `runTransaction`, and `loadAdminOrder` in `src/modules/orders/orderFulfillment.service.js`.

## Detail projections can combine incompatible Order and Shipment states

**Confirmed — medium.** Both detail paths load Order before a separate Shipment query with no shared snapshot. A `RECORD_SHIPMENT` commit between those reads can produce admin detail with Order PACKED, the old version, Shipment SHIPPED, and `availableActions` still advertising `RECORD_SHIPMENT`. `orderService.getMineByNumber` can similarly return customer `tracking.status: PACKED` with `tracking.shipment.status: SHIPPED`; later shipment transitions have the same race.

Build order-plus-shipment detail in one database operation or a read-only snapshot transaction. Affected symbols: `loadAdminOrder` in `src/modules/orders/orderFulfillment.service.js`, `orderService.getMineByNumber` in `src/modules/orders/order.service.js`, and `customerTracking`/`availableOrderActions` in `src/modules/orders/order.dto.js`.

## MANUAL is used as the shipment identity namespace

**Likely — medium.** `shipmentSchema` uniquely indexes `{ adapter, shipmentId }` and `{ adapter, trackingId }`, but every shipment has adapter MANUAL. Different couriers therefore cannot reuse those identifier values, while the supplied `courier`/`awb` pair has no uniqueness fence and can be assigned to multiple orders. If AWB is the carrier identity represented by this API, the current indexes permit duplicate physical shipment identity while creating unrelated cross-courier conflicts.

Define canonical identifier scopes and encode them in validation and indexes, such as normalized courier plus AWB and courier-scoped public/private IDs where those IDs are not globally unique. Retain `{ order, direction }` as the whole-order fence. Affected symbols: `shipmentSchema.index` in `src/modules/shipping/shipment.model.js`, deployed through the Shipment registration in `scripts/syncIndexes.js`.

</details>
