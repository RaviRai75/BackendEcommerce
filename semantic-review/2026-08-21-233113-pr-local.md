# Transaction-bound fulfillment responses with courier-scoped shipment identity

Task 23 now returns an action DTO assembled inside the mutation transaction and reuses it after marker-confirmed ambiguous commits, removing the mandatory post-commit reload. Ordinary detail reads fence the Order/Shipment join with bounded `__v` rechecks, and shipment identity is now courier-scoped. Two remaining gaps affect transaction execution and admin search completeness. **Watch for:** **confirmed (high)** Mongoose runs the Order and Shipment populate paths concurrently on one transaction session; **confirmed (low)** customer-backed admin search considers at most 500 matching users.

**Verdict**: NEEDS_CHANGES

## High-level view

Known and marker-reconciled commits return the same transaction-created `adminOrderDetail`. The outer action-detail queries are sequential and snapshot-bound, but each multi-path Mongoose `populate` still fans out into concurrent session operations.

Customer and ordinary admin details retry at most three times unless Order retains the `__v` read before Shipment. Because every D32 shipment transition increments Order `__v` atomically, the prior mixed Order/Shipment lifecycle response is closed.

Shipment creation derives immutable `courierKey` server-side using normalized courier text. Unique courier-key/AWB, tracking-ID, and shipment-ID indexes replace the MANUAL-global namespace while retaining unique order/direction.

The ADMIN `q` filter materializes matching customers with a hidden 500-user cap, so broad valid terms return an incomplete order set.

<details><summary>Details</summary>

## Transaction action detail still performs parallel population queries

**Confirmed — high.** `loadAdminOrder` attaches both `ORDER_POPULATIONS` to the session-bound Order query and both `SHIPMENT_POPULATIONS` to the session-bound Shipment query. Installed Mongoose 8.9.5 creates one promise per populate path and awaits `Promise.all`, so the User queries for `user` and `statusHistory.actor`, and those for `recordedBy` and `milestones.actor`, are not sequential.

Parallel operations on one MongoDB transaction session are unsupported and can roll back a valid fulfillment action before commit. Populate each path in a separate awaited session-bound operation, or load the referenced people through explicitly sequential queries before constructing the DTO. Affected symbols: `ORDER_POPULATIONS`, `SHIPMENT_POPULATIONS`, and `loadAdminOrder` in `src/modules/orders/orderFulfillment.service.js`.

## Customer-backed admin search truncates valid matches

**Confirmed — low.** `adminFilter` applies `.limit(500)` to matching users before adding their IDs to the Order filter. A common name or email domain can therefore omit valid orders from both the page and reported total.

Join customer criteria without an arbitrary hidden cap, or expose a narrower search contract that cannot exceed the bound. Affected symbol: `adminFilter` in `src/modules/orders/orderFulfillment.service.js`.

</details>
