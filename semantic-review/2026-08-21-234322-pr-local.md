# Database-side ADMIN order search closes the fulfillment review

Task 23 adds versioned ADMIN fulfillment actions, transaction-coupled manual shipment tracking, customer-safe tracking, and atomic pre-shipment cancellation. The final revision moves customer matching into the Order aggregation while preserving order, item, and customer search behavior. It removes application-side customer-ID materialization and BSON `$in` construction without reopening prior transaction, consistency, authorization, cancellation, audit, validation, or shipment-index findings. **Watch for:** no confirmed high- or medium-severity correctness blockers in the reviewed Task 23 scope.

**Verdict**: APPROVED

## High-level view

ADMIN `q` search applies fulfillment/payment filters before an `_id`-correlated User lookup, matches order number, item name/SKU, and customer name/email/phone, then facets the shared result into a stable newest-first page and exact total. Literal case-insensitive matching is retained without an unbounded Node array or BSON command.

The aggregation projects the existing ADMIN list allowlist. Customer phone remains searchable but is removed before DTO construction; addresses, detailed line data, history, reconciliation markers, and shipment/provider identifiers cannot enter the list response.

Fulfillment actions retain one snapshot transaction for Order CAS, Shipment changes, cancellation release, strict audit creation, and response construction. Majority-marker reconciliation reuses that transaction-built response; ordinary tracking joins remain Order-version fenced, and ADMIN routes remain database-authorized, strictly validated, and `private, no-store`.

## Faceted User lookup preserves search and list behavior

`status` and `paymentStatus` constrain the Order set before the join. The escaped expression then covers `orderNumber`, `items.productName`, `items.sku`, and joined customer `name`, `email`, and `phone`; `$facet` computes rows and count after that shared match, with `createdAt: -1, _id: -1` applied before skip/limit. `allowDiskUse(true)` permits database-side spill, while Node receives only the selected page and scalar count.

The post-match projection retains only list DTO inputs and strips the lookup-only phone field. Search therefore does not widen the ADMIN response relative to the non-search list.

## Prior fulfillment blockers remain closed

Accepted actions compare and increment Order `__v`; couple Shipment creation/advancement, immutable delivery time, cancellation inventory/coupon release, and strict audit to the same transaction; and reconcile ambiguous commits through the private action marker. Session-bound populations are sequential, ordinary Order/Shipment joins use bounded version rechecks, and courier-normalized AWB/tracking/private-ID plus order/direction unique indexes remain registered for synchronization.
