# Best-effort abandoned-cart episodes without a durable ordering fence

Task 36 adds a private, 30-day projection of authenticated cart mutations and closes an eligible episode after an exact order cart clear. Projection failures remain outside cart and order correctness, and the snapshot excludes contact, consent, device, and message data. The partial unique index limits each owner to one `OPEN` row, but wall-clock timestamps are being used as the mutation-order authority outside the Cart write. **Watch for:** **confirmed (high)** delayed older activity can overwrite newer snapshots or reopen after `CLEARED`/`CONVERTED`; **confirmed (medium)** timestamp equality can let conversion close a newly started post-checkout episode; **confirmed (medium)** no Task 36 tests exercise lifecycle, ordering, index, or best-effort behavior.

**Verdict**: NEEDS_CHANGES

## High-level view

Authenticated cart writes project their hydrated postimage; an empty result closes the current episode, while an exact committed checkout clear triggers conversion. Reads, quotes, public routes, notifications, reminders, and consent inference do not call the projection.

`lastActivityAt` is captured after the Cart write but outside its atomic boundary. Async scheduling and catalogue hydration can reorder projections relative to their source Cart writes, while the create fallback checks no newer closed episode before opening another row.

Conversion is gated by the order placement timestamp rather than the identity or revision of the Cart snapshot cleared by the transaction. Index synchronization includes the partial-unique and TTL indexes, but no tests assert the new lifecycle or its concurrency behavior.

## Activity timestamps do not serialize Cart writes

**Confirmed — high.** `cartDtoAfterMutation` receives a Cart postimage, then assigns `activityAt` and hydrates catalogue data before writing the event. Two Cart writes can commit in one order while their continuations obtain timestamps or finish hydration in another; an older postimage can therefore receive the later timestamp and overwrite a newer `OPEN` snapshot despite the `lastActivityAt: { $lte: activityAt }` filter.

If that older nonempty projection is delayed across a newer empty mutation, the newer request closes the owner's `OPEN` row as `CLEARED`. The delayed update then finds no `OPEN` row, and its fallback `create` succeeds because the partial unique index also covers only `OPEN`. The same sequence reopens stale activity after checkout changes the old row to `CONVERTED`. Duplicate-key retry only handles a concurrent winner that remains `OPEN`; it never checks whether a newer closed transition already won.

Generate a monotonic activity revision in the same atomic Cart mutation that produces the returned lines, carry it into the snapshot, and serialize every owner transition against a durable owner-level cursor/CAS. Creation must reject revisions older than the latest `OPEN`, `CLEARED`, or `CONVERTED` transition; `activityAt` should remain metadata, not ordering authority. Affected paths: `cartDtoAfterMutation` in `src/modules/cart/cart.service.js` and `writeCartActivity` in `src/modules/cart/abandonedCartEvent.service.js`.

## Conversion is not bound to the cleared Cart snapshot

**Confirmed — medium.** Order placement records `placedAt` before transaction commit and calls `recordConversion` afterward. Conversion closes any `OPEN` row with `lastActivityAt <= placedAt`; because JavaScript dates have millisecond precision, a mutation accepted immediately after commit can start a new episode at the same timestamp and then be converted by the older order. The live Cart is nonempty, but no `OPEN` candidate remains.

Return the Cart activity revision from the transaction's exact compare-and-clear and close only the episode represented by that revision. A post-commit mutation must have a greater revision and remain `OPEN`, even within the same millisecond. Affected paths: the `cartCleared` branch in `src/modules/orders/order.service.js` and `writeConversion` in `src/modules/cart/abandonedCartEvent.service.js`.

## Task 36 lifecycle and failure isolation are untested

**Confirmed — medium.** Neither `tests/modules/cart/cart.test.js` nor `tests/modules/orders/order.test.js` imports or asserts `AbandonedCartEvent`, and no dedicated Task 36 test exists. The 26 targeted tests pass, but do not establish snapshot contents, unavailable-value handling, clear/convert transitions, partial-unique and TTL behavior, read inactivity, swallowed projection failures, or delayed/equal-time ordering.

Add focused service/integration coverage that controls projection completion order and wall-clock equality, validates lifecycle/index invariants, and proves projection failure cannot change Cart or Order outcomes. Include absence assertions for GET/quote and notification paths.
