## ROTATED replay detection closes both successor-creation race orderings

The conditional transition from active to `ROTATED` admits one rotation winner. A loser now triggers account-wide reuse handling whenever it observes that state, including before `replacedBy` is written, and revocation increments `User.tokenVersion` before sweeping active sessions.

The winner inserts its successor with the claimed session's epoch and checks the user epoch again before returning credentials. If reuse handling bumps the epoch before that check, the winner revokes the successor and fails; if the check completes first, the following sweep catches the successor. A successor inserted after the sweep fails the post-insert check, leaving no interleaving with a usable replacement session or current-epoch access token.

Password reset commits the password hash, reset generation, and token epoch in one user-document write. Authenticated password change compare-and-sets the previous hash and epoch, so concurrent security changes cannot silently overwrite each other and cleanup failure cannot preserve old credential validity.

## PaymentEvent receipts are append-only across model mutation paths

The schema makes status immutable and rejects existing-document saves. Query middleware rejects updates, replacements, and deletions, while document deletion and compiled-model `bulkWrite` are also blocked. Creation remains available for provider-event ingestion, but existing evidence cannot be rewritten or removed through the Mongoose model API.

## Direct customization indexes remove both blocking sorts

`listAdmin` accepts `status` without `priority` and sorts by `{ createdAt: -1, _id: -1 }`. The added `{ status: 1, createdAt: -1, _id: -1 }` binds that filter directly to the complete sort sequence instead of crossing an unbound priority key. `{ status: 1, priority: 1, createdAt: -1, _id: -1 }` remains for combined filtering.

`listAdminOrders` independently accepts `paymentStatus` with the same deterministic order. `{ paymentStatus: 1, createdAt: -1, _id: -1 }` removes the unbound production and fulfillment keys from that path, while the wider payment/production/fulfillment index remains intact. Direct production, fulfillment, and completion indexes cover their independent filters, and unfiltered scans have the exact pagination sort.

## Reconciliation and list indexes match production ordering

Expired-upload reconciliation has two `$or` branches sorted by ascending `issuedAt` and `_id`. The status/issued-time index serves pending, expired, and rejected uploads; the status/deletion-reason/issued-time index serves retryable reconciliation deletions. The pre-existing ready-editorial index continues to serve its separate scan.

Unread notifications now include `_id` after `createdAt`. Support administration has unfiltered, status-only, priority-only, combined status/priority, and category paths ordered by `updatedAt` and `_id`. Customization covers each independently optional administrative axis, while review administration gains unfiltered and product-leading pagination paths alongside its existing moderated-list compounds.
